# 蓝牙音频接收器 3.0-beta6

作者：橘橙的记忆。

检测当前固件的蓝牙接收代码、原生库、控制接口和 root 能力，再选择适用的配置方式。音频接收、解码和播放使用系统已有的 A2DP Sink 实现。

## 通用适配

beta6 按固件能力组合配置与控制路径，不读取机型来决定是否支持：

| 能力 | 当前支持的路径 |
| --- | --- |
| 角色配置 | AOSP A2DP / AVRCP 属性；蓝牙原生库实际引用的厂商角色属性 |
| 资源覆盖 | 动态生成覆盖；内置资源辅助 APK 与 root idmap2；系统已有音频焦点配置 |
| 服务获取 | Adapter Binder；系统框架 ProfileConnector；应用绑定后 root peekService |
| 接口调用 | 旧式直接返回；AttributionSource 直接返回；AttributionSource 与 SynchronousResultReceiver 回传 |

AOSP 方案不要求蓝牙 APK 位于 `/apex`，也不按 Magisk / KernelSU 选择接口。厂商方案必须发现蓝牙原生库中的对应属性引用，并确认发送、接收、媒体控制及焦点资源，才允许使用；没有引用证据时不猜测或改写厂商属性。可用的资源覆盖方式与接口 ABI 分开选择。

完整检测除检查代码、原生库、配置与工具外，还在 root 辅助进程实际读取适配器信息，并尝试调用当前音频服务。接口调用发生异常时不会继续显示可控制。蓝牙关闭或旧接口需要管理界面绑定时，会分别报告对应状态；不会为检测而开启蓝牙。切换后检查目标服务及对立服务，失败时尝试回滚。

方案不包含机型白名单。它仍然依赖系统已有的接收实现，不能补回固件删掉的代码，也不会给未知的配置协议假定一种写法。检测报告会列出各项策略、是否需要资源辅助 APK、实际调用结果及缺少的条件。当前属性协议与资源辅助 APK 的支持边界见验证记录。

## 支持范围

- Android 11 / API 30 及以上、已授权 root，且固件提供可验证的 A2DP Sink、媒体控制与原生接收实现。
- 角色配置需满足上表中的属性协议，资源与控制接口也需通过完整检测；Android 版本或 root 管理器名称本身不是通过条件。
- 采用资源辅助 APK 的路径会在 `/data/app` 安装内置的无代码资源包，以 root 生成映射，不挂载或修改系统分区。当前内置资源包针对 `com.android.bluetooth`；动态覆盖路径也可使用检测到的 Google 蓝牙包。
- 2.0 已安装且启用的兼容模块可继续使用；3.0 不再内置或安装模块。
- 发现代码标识或完成控制调用，都不等于实际播放已通过。连接、音频路由和播放需单独验证。

## 使用

1. 安装 APK，打开后点击“完整检测”，允许 root。
2. 检测通过后选择“音箱接收”。
3. 点击“开始配对”，在发送端搜索本机并配对，选择本机作为媒体输出。
4. 选择“普通发送”可恢复向耳机或音箱输出音频。
5. “开机默认”可选择普通发送、音箱接收，或记住上次模式；修改默认值不会立即切换。

检测只读取信息。切换模式会断开现有蓝牙连接，保留配对记录和蓝牙开关状态。失败时尝试恢复切换前的配置。

“恢复原配置”恢复首次切换前保存的蓝牙角色属性，并停用本应用的资源覆盖和开机自动恢复；涉及组件启用的路径也会恢复原组件状态。卸载 APK 前应先执行恢复；直接卸载不会自动撤销 root 配置。资源辅助 APK 停用后可单独卸载。旧系统兼容模块的恢复会切回发送模式、把开机默认改为发送，其完整卸载仍需在 root 管理器中进行。

界面区分“已连接”“蓝牙音频会话活动”和实际音轨观察。“完整检测”的报告可显示本次是否观察到活动蓝牙音轨、采样率和输出路由。报告支持复制。

## 开机恢复

无需本应用模块的后端通过系统启动广播安排 JobScheduler 任务，重新应用保存的运行时属性和资源覆盖。APK 需要保留且已获得 root 授权；系统若限制启动任务或取消 root 授权，可能无法自动恢复。启动任务错误会保存在应用的设备保护存储中。

应用不修改 USB 调试、开发者选项或网络 ADB 端口。日常使用不需要连接电脑。

## 构建

使用 Linux x86_64：

```sh
bash bootstrap-toolchain.sh
bash build.sh
```

工具链使用 OpenJDK 17、Android SDK Platform 30 和 Build Tools 30.0.3，不依赖 Gradle。已有工具链可指定：

```sh
TOOLS=/absolute/path/to/toolchain bash build.sh
```

输出为 `dist/Android-A2DP-Sink.apk`。构建会把 `overlay/` 生成的资源辅助 APK 内置到管理 APK；仓库保留的 `module/` 是旧版兼容资料，不会打包。

首次构建生成 `signing/local-speaker.jks`。覆盖升级必须保留自己的原签名；签名文件不包含在源码中。

本工作区的编译服务器通过本地 `127.0.0.1:7778` 连接，默认账号 `tomid`。`sh tools/remote-build.sh '远端命令'` 使用该入口；可通过 `A2DP_BUILD_HOST`、`A2DP_BUILD_PORT`、`A2DP_BUILD_USER` 覆盖。密码辅助程序可放在 Git 忽略的 `.local/ssh-askpass.sh`，或用 `A2DP_SSH_ASKPASS` 指定。源码不包含密码或签名私钥。

## 验证

连接已授权 root 的 Android 设备后，可只读检查安装的 APK：

```sh
python3 tests/device_smoke.py --serial DEVICE_SERIAL
```

对通过检测的无模块后端，可运行会临时断开蓝牙连接的集成测试：

```sh
python3 tests/device_smoke.py --serial DEVICE_SERIAL --exercise
```

接口兼容测试只需 JDK 17，不需要连接设备：

```sh
sh tests/test-bluetooth-abi.sh
```

测试最终尝试恢复执行前的模式、开机默认、自动恢复设置和蓝牙开关，并重新请求连接原来的音频设备。beta6 的实际测试边界见 [docs/VALIDATION-BETA6.md](docs/VALIDATION-BETA6.md)，历史音轨观察见 [docs/VALIDATION.md](docs/VALIDATION.md)。

beta4 会跳过已经生效的重复开启和重复恢复操作；测试也会检查这些操作没有增加蓝牙开关记录。手动切换模式会标记当前启动周期已经处理，避免延迟的开机任务覆盖刚选择的模式。

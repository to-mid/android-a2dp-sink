# 3.0-beta7 验证记录

日期：2026-11-02。版本：`9 / 3.0-beta7`。

## 方案选择

新增“适配方案”下拉菜单，默认自动，手动选项由当前完整检测结果生成。支持 AOSP / 厂商属性与动态覆盖 / 资源包 / 系统默认资源的有效组合；已有兼容模块仅在没有独立方案时作为兼容后端保留。

自动模式优先使用已验证接收切换的缓存。没有可用缓存时，按当前属性引用、资源和工具条件选择候选；候选失败后先回滚，再尝试下一项。手动模式只尝试指定组合，失败后保持原选择和原运行状态。蓝牙关闭时不为切换开启蓝牙，下一次通过应用开启时再运行验证。

切换后检查目标 A2DP 服务、对立 A2DP 服务、接收端 AVRCP 控制服务、本机音频 UUID 和实际可用的控制接口。旧式接口无法直接取得服务时保留界面绑定路径。“已验证接收切换”不表示实际播放通过。

## 状态与升级

方案缓存更新为 revision 2，使 beta6 的旧选择失效。应用设置保存 `schemePreference`，实际选择存入 `adaptation.planId`；缺少选择字段时按 `auto` 处理。

跨方案操作补齐六项属性及服务组件的原始值，已有原始值不被覆盖；每次尝试另外保存即时属性、组件、应用覆盖状态、运行模式、蓝牙开关和设置。失败时恢复即时状态；新安装且未成功使用的资源辅助 APK 会在回滚时卸载。回滚失败则停止后续尝试。

`status` 返回当前偏好、实际方案、接收切换验证标志和 `selectionAttempts`，可以区分自动模式尝试过的失败方案与最终成功方案。

## 11 Ultra 实测

设备：小米 11 Ultra / star / M2102K1C，Android 14 / API 34，OS2.0.7.0.UKACNXM，Magisk 27.0。

从 beta6 原有四项属性备份升级。自动选择 `vendor-properties/fabricated-overlay`，成功启动 A2dpSinkService、AvrcpControllerService，并公布 110B；切回发送后公布 110A。

完整设备控制回归通过：

- 只读诊断与状态查询，诊断前后系统快照一致。
- 双向角色切换、对应服务及本机 UUID。
- 蓝牙关闭时切换仍保持关闭，再开启后验证角色。
- 重复开启、重复恢复不增加蓝牙开关记录。
- 开机恢复函数重复调用与原始属性恢复。
- 旧配置补齐另一组属性和原始组件状态。

方案专用验证通过：

1. 在发送状态固定 AOSP 动态覆盖，选择保存成功；尝试接收失败，属性、设置、有效覆盖、辅助包状态与尝试前一致，偏好仍保持手动 AOSP。
2. 切回自动后成功进入厂商接收模式。
3. 在接收状态指定厂商资源包，资源覆盖失败后恢复接收状态及原自动偏好；没有留下辅助包。
4. 在发送状态注入“已验证但当前失效”的厂商资源包缓存，模拟旧方案失效。自动接收先尝试资源包并失败，确认回滚后使用动态覆盖成功。`selectionAttempts` 顺序为资源包失败、动态覆盖成功。
5. 最终恢复自动、普通发送、蓝牙开启、开机默认发送及关闭的自动恢复标志。

完整控制回归和故障回退使用首个 beta7 构建。随后仅缩短菜单标签、调整选择控件布局，并让状态读取当前有效方案的验证标志；最终构建再次通过接口测试及安装包的只读诊断、状态检查。

接口单元测试覆盖双协议候选保留、候选顺序、资源条件、手动方案 ID、未知方案拒绝，以及原有直接 / AttributionSource / 回传接口等用例。

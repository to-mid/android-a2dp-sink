# 3.0-beta8.2 验证记录

日期：2026-11-21。基线为 v3.0-beta7，包含 R8、R8.1 的开机恢复、界面刷新、模式切换及连接结果判断修复。

## 本轮设备证据

小米 10S / Android 11 / MIUI 12.5.8，配对 Win11。关闭手机蓝牙后重新开启，从手机发起连接。

1. 修改前，蓝牙进程在 SDP 查询失败后每约 60–100ms 再发起连接。精确提取手机自带 Bluetooth.apk 的 dex 显示：接收状态机的 `mIncommingConnection` 只初始化为 false，没有在收到入站连接事件时赋 true，连接事件再次触发原生连接入队。
2. 原生队列保护加入后，本轮 13:18、13:19、13:20 的主动连接均只记录一次失败，未继续出现密集循环。仍存在真实的 `SDP record not found` / `BTA_AV_OPEN_EVT::FAILED status:2`，所以不能认定主动连接已经修好。
3. 手机系统的“已连接”不代表 A2DP 已连接；RootCommand 查询 `connected` 为空。Win11 对应音频端点处于断开状态；手机 AudioSink 驱动存在。
4. 接收服务在后台运行，但 root `app_process` 不能以普通应用身份绑定服务。增加短时前台 `ProfileAccessService`，由已注册应用进程建立无 action 的绑定，再由 root 查询接口。服务 8 秒后自行结束；没有循环重启蓝牙的后台任务。实测应用在后台时 `profileReady:true`，短时服务退出后仍可查询。

## 验证

- ABI、适配候选与连接状态机测试通过。
- 开机脚本的 5 项重试、停止条件、卸载/清数据测试通过。
- 实际 ARM64 指令的 12 项仿真通过：AVRCP 空/非空列表，连接空闲及状态 1–4、未知状态、不同设备、第二槽位和未初始化；验证队列参数及寄存器恢复。
- 编译与 APK 签名校验通过，沿用 R7 签名。
- 当前活动模式是接收，保存的开机默认是发送，开机恢复与 root 钩子开启。本轮没有重启手机验证，不宣称完成重启回归。

## 重新配对后的播放

用户从 Win11 删除旧配对并重新配对后确认“正常播放”。手机查询已连接 TO_MID，`sessionActive:true`；Win11 对应音频端点状态为 OK。临时设置的本机设备类型查询为 `240414`，但 Windows 仍返回旧的 `5e020c`，端点名称仍是“电话”。因此，本次证据只能证明重新配对后播放恢复，不能证明设备类型是原因；设备类型修改暂不纳入正式代码。
